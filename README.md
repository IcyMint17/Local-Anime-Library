# 本地番剧媒体库管理器

把你硬盘上按字幕组原始命名堆放的番剧文件，整理成一个像 Animeko 那样的可视化番剧库：自动扫描、自动识别番剧、拉取封面与剧集信息，并手动记录看到第几集。

只读扫描——**不会移动、重命名或删除你的任何文件**。

## 快速开始

1. 需要 Node.js **22.5 或更高版本**（`node --version` 查看）。不需要 `npm install`，本项目零第三方依赖。
2. 双击 `start.cmd`。
3. 浏览器会自动打开 `http://127.0.0.1:5178`，点右上角「扫描」开始整理。

第一次扫描要访问 Bangumi 抓取元数据和封面，23 部番大约 1 分钟；之后有缓存，重复扫描只要几秒。

## 它是怎么工作的

```
扫描目录 → 解析文件名/文件夹名 → 去 Bangumi 搜索并打分 → 落地到本地 SQLite
```

1. **扫描**：递归遍历扫描目录，只挑视频文件（mkv/mp4/avi/…），自动跳过字体、字幕、扫描图、CD 音轨和 BD 菜单。
2. **解析**：从发布文件夹名与文件名里提取番剧标题、季数、集号，以及判断这是正片、特别篇还是剧场版。支持 `- 01`、`[01]`、`01v2`、`[12END]`、`S01E03`、`第3集`、`11.5` 半集、`NCOP/NCED/特典/小剧场` 等真实命名。
3. **识别**：用文件夹名（通常是中文）和文件名解析出的标题（通常是罗马音）分别去 Bangumi 搜索，再按名称相似度、季数、集数、媒介类型、搜索结果排名综合打分。只有最高分足够高、且明显领先第二名时才自动绑定，否则标记为「待确认」。

   低置信度时会自动拉取候选项的详情，用 Bangumi 的**别名**再算一遍——这就是 `GIRLS BAND CRY` 能正确对上「少女乐队的呐喊」的原因。

4. **落地**：番剧、文件、剧集、观看记录都存进 `data/library.db`，封面缓存在 `data/covers/`。扫描过一次之后断网也能正常浏览。

## 观看记录

- 每集一个勾选框，精确到集。
- 整部番的 **未看 / 观看中 / 已看完** 由集进度自动推导，不会出现两边对不上的情况。
- 特别篇、NCOP/NCED、小剧场、剧场版单独成列，**不计入正片进度**。
- 提供「全部标记已看」「全部标记未看」一键操作。
- **双击任意一集**就会用系统默认播放器打开对应视频（也可以点悬停出现的「▶ 播放」按钮）。

## 界面

- **顶栏**：左边只有图标和「本地番剧媒体库」，搜索框永远在窗口正中，右上角是深色 / 亮色切换。
- **深色 / 亮色**：点右上角的太阳 / 月亮图标切换，选择记在浏览器里。
- **侧边栏可收起**（点侧边栏右上角的箭头），收起后只剩图标；状态记在浏览器里。扫描和设置按钮在左下角，下面是番剧数、观看中、已看完和上次扫描时间。
- **主页顶部**是「继续观看」：按最近观看时间排序，显示下一集是哪一集，点一下直接进详情。只在「全部」分类里出现。
- **主题配色可调**：设置里有 6 套预设加一个取色器，只影响按钮、进度条、选中态等强调色。

应用图标是 `public/icon.jpg`，同时用作页面左上角的标志和浏览器标签页图标。

详情页在桌面尺寸下是左右分栏：左栏放封面、标题、评分、简介和来源路径，右栏是可独立滚动的剧集列表（正片 / 特别篇 / 剧场版 / 未收录 分标签）。所以哪怕一部番有五十多个文件，页面也不会被撑长，封面和信息始终留在屏幕上。窄窗口下自动改为上下堆叠。

## 手动纠错

自动识别不是万能的。遇到下面这些情况，在详情页点「重新匹配…」即可：

- 搜不到，或者匹配到了相邻的一部（比如同名的第二季）。

详情页同时会列出「Bangumi 上有、本地没有」的剧集，方便你知道还缺哪几集。

已知会被标成「待确认」的典型场景：文件夹名只说「某某剧场版」，真正的副标题只在文件名里（例如 `中二病也要谈恋爱剧场版` + `-Take On Me-`）。在候选列表里点正确的那一条即可。

### 集号对应关系

本地文件的集号经常和 Bangumi 对不上，程序会**自动推断**，不需要你算偏移量：

| 情况 | 本地集号 | Bangumi 集号 | 自动得出 |
| --- | --- | --- | --- |
| Re:Zero 第四季 丧失篇 | 67–76 | 67–77（Bangumi 的连续编号） | 一一对应 |
| 无职转生 第二季 | 0–24（含第 00 集） | 0–24 | 一一对应 |
| 无职转生 ～…～ 第2部分 | 12–24 | 12–23 + SP 24 | 一一对应，第 24 集是特别篇 |
| 孤独摇滚！ | 1–12 + 11.5 | 1–12 + SP 11.5 | 一一对应，11.5 是特别篇 |

推断规则是「让尽量多的本地集落在 Bangumi 剧集上」，平手时优先让两个序列从开头对齐。详情页左栏会显示当前对应关系和「N/M 集对得上」。

### 正片与特别篇以 Bangumi 为准

Bangumi 会把条目里的章节分成**正片**和**SP / OP / ED / 预告**。程序会把这些全部取回来，只要本地文件对上的是一条非正片章节，就自动归入「特别篇」、不计入正片进度——不需要靠文件名猜。

两个容易踩的坑已经处理掉了：

- **SP 用自己的一套编号**。「孤独摇滚！」的正片是 1–12，SP 也是 1、2、3、11.5。程序按「正片优先」配对，所以 `[01]` 是正片，`[11.5]` 才是特别篇。
- **Bangumi 的连续编号（sort）才是准的**。无职转生 第2部分、Re:Zero 第四季这类条目的集号不是从 1 开始，程序直接用 Bangumi 的编号，因此和本地文件名天然对齐。

个别文件夹会混用两种编号（例如 Re:Zero 第三季里既有 `01`–`14` 又有 `66END`）：程序先按偏移映射，只有当偏移落空时才会把原集号当成正确值。

如果推断得不对，在详情页点「重新匹配…」，对话框里就能改：勾「自动推断」由程序重算，取消勾选后直接填「本地第 ___ 集 = Bangumi 第 ___ 集」。手动指定的对应关系会锁定，重新扫描不会被覆盖。

## 配置

界面上点「设置」可以改，配置存在项目根目录的 `config.json`：

| 项 | 说明 |
| --- | --- |
| `scan.dirs` | 扫描目录，可以配多个 |
| `proxy` | `auto`（默认，自动探测）／留空（直连）／`http://127.0.0.1:7890` 这样写死 |
| `metadata.matchThreshold` | 自动匹配阈值，越高越保守 |
| `metadata.matchMargin` | 第一名必须领先第二名多少分才会自动绑定 |
| `metadata.accessToken` | 可选。填 Bangumi 个人令牌可以提高接口配额 |

Bangumi 在国内通常可以直连。如果机器需要走代理，程序会按这个顺序自动找：环境变量 `HTTPS_PROXY` / `HTTP_PROXY` → Windows 系统代理设置 → 常见本地端口（7890 / 7891 / 7892 / 10809 / 1080 / 8080 …）。找到之后会实际连一次 Bangumi 验证可用性，结果缓存在 `config.json` 里。

## 命令行

```bash
node src/main.js                 # 正常启动
node src/main.js --scan          # 启动并立刻扫描一次
node src/main.js --no-open       # 不自动打开浏览器
node src/main.js --port 6000     # 换端口
```

## 开发

```bash
node --test                      # 全部测试
node tools/inspect-library.mjs   # 看扫描/分组结果，不发网络请求
node tools/inspect-db.mjs        # 看本地数据库内容
node tools/evaluate-matching.mjs # 用真实库跑一遍识别准确率（会联网）
```

代码结构：

```
src/
  main.js             入口：配置、数据库、代理探测、启动服务
  config.js           配置读写与代理自动探测
  net/http.js         支持 CONNECT 代理隧道的 HTTP 客户端（重试 + 限流）
  db/                 SQLite 建表与全部读写
  scan/               遍历、文件名解析、分组、扫描流水线
  meta/               Bangumi 客户端、候选打分、封面缓存
  library/progress.js 观看状态推导
  api/routes.js       REST 接口
  server.js           静态文件 + JSON API 服务
public/               前端（原生 HTML/CSS/JS，无构建步骤）
test/                 node:test 测试，全部使用真实文件名
```

零第三方依赖是刻意的：不需要 `npm install`，离线可用；将来打包成桌面应用时体积小，也不会有原生模块编译问题。

## 桌面版（Electron）

浏览器版和桌面版共用同一套后端代码（`src/app.js` 的 `startLibraryApp()`），
桌面外壳只是换了个加载方式，没有第二份实现。

```
cd desktop
npm install          # 首次需要，从镜像下载 Electron 二进制
npm run make-icon    # 由 public/icon.jpg 生成 icon.ico
npm start            # 开发模式运行
npm run pack         # 打包到 desktop/dist/AnimeLibrary-win32-x64
```

打包脚本会先把 `src/`、`public/`、`config.json` 和外壳文件整理进 `staging/`，
再交给 electron-packager 打成 `app.asar`。

| | 浏览器版 | 桌面版 |
| --- | --- | --- |
| 代码位置 | 项目目录 | `resources/app.asar`（只读） |
| 数据目录 | `<项目>/data` | `%APPDATA%\AnimeLibrary\library` |
| 设置文件 | `<项目>/config.json` | 同数据目录下 |
| 端口 | 5178（可在设置里改） | 每次启动由系统分配 |

桌面版的启动日志写在 `%APPDATA%\AnimeLibrary\startup.log`——窗口应用没有控制台，
启动失败时先看它。菜单「帮助 → 打开数据文件夹」可以直接定位库文件。

> 桌面版使用独立的数据目录，所以第一次启动会重新扫描一遍；这不影响命令行版的库。
